# 01. アプリケーション要件定義書

## 1. プロジェクト概要

### 1.1. 目的

React Router の最新安定版を「SSRフレームワーク」として利用し、特に `loader` および `action` 機能を実装する技術課題を遂行する。この課題の要件を満たすための、最小限の機能を持つ Web アプリケーション（ブログアプリ）を構築する。

### 1.2. 背景

React/TypeScript 未経験者が、指定されたモダンな技術スタックをキャッチアップし、クリーンなコードでの実装能力を実証することを目的とする。AI駆動開発（Codex）の活用も要件に含まれる。

## 2. 技術要件

* **TypeScript:** 最新安定版
* **React Router:** 最新安定版
    * **SSRフレームワークとして利用する:** 公式フレームワークモード（[[installation]](https://reactrouter.com/start/framework/installation)）を採用し、サーバー・クライアント双方でルートを管理する。
    * **`loader` / `action` の実装:** データ取得（`loader`）とデータ操作（`action`）を、React Router の機能を用いて最低1つ以上実装する。
* **データストア:**
    * DB（MySQL, PostgreSQLなど）やオブジェクトストレージ（S3など）は**使用しない**。
    * データはサーバーサイドの**インメモリ**（グローバル変数など）で保持する。サーバーを再起動するとデータは消滅する前提で良い。
* **コード品質:**
    * プロダクションレディである必要はないが、クリーンなコード（適切なコンポーネント分割、TypeScriptの型定義）を意識する。

## 3. データ定義

### 3.1. 投稿 (Post)

アプリケーション内で扱う中核データ（インメモリで保持）。

| フィールド | 型 | 説明 |
| :--- | :--- | :--- |
| `id` | `string` | 一意な識別子 (例: `crypto.randomUUID()`) |
| `title` | `string` | 記事のタイトル |
| `content` | `string` | 記事の本文 |
| `createdAt` | `Date` | 作成日時 |

## 4. 機能要件

実装する機能を、必須技術要素（`loader`, `action`）と紐付けて定義する。

### 4.1. 記事一覧ページ

* **URL:** `/`
* **機能:**
    1.  インメモリに保存されている全記事の「タイトル」を一覧表示する。
    2.  各タイトルは、該当する記事詳細ページ (`/posts/:id`) へのリンクとする。
    3.  「新規投稿ページへ」のリンク (`/posts/new`) を表示する。
* **必須技術要素:**
    * **`loader` (実装必須):** サーバーサイドで全記事データを取得し、ページに渡す。

### 4.2. 記事詳細ページ

* **URL:** `/posts/:id` (動的ルート)
* **機能:**
    1.  URLの `id` に一致する単一の記事の「タイトル」と「本文」を表示する。
    2.  記事を削除するための「削除ボタン」を設置する。
    3.  「一覧へ戻る」リンク (`/`) を表示する。
* **必須技術要素:**
    * **`loader` (実装必須):** `params.id` を使い、サーバーサイドで特定の記事データを取得する。
    * **`action` (実装必須):** 「削除ボタン」の送信（HTTP `DELETE` 推奨）を処理する。インメモリから該当記事を削除し、一覧ページ (`/`) へリダイレクトする。

### 4.3. 記事新規作成ページ

* **URL:** `/posts/new`
* **機能:**
    1.  「タイトル」と「本文」を入力するフォームを表示する。
    2.  「投稿する」ボタンを設置する。
* **必須技術要素:**
    * **`action` (実装必須):** フォーム送信（HTTP `POST`）を処理する。フォームデータから記事を作成し、インメモリに保存する。成功後、一覧ページ (`/`) へリダイレクトする。

## 5. 非機能要件

* **データ永続化:** サーバーのインメモリ上でのみデータを保持する。サーバープロセスが終了するとデータは失われるものとする。
* **スタイリング:** CSSによるデザインは必須としない。HTMLの標準要素のみで機能が確認できれば良い。
* **エラーハンドリング:** (推奨) `loader` で記事が見つからない場合、React Router の `errorElement` を用いて「記事が見つかりません」といったエラー表示を行う。

## 6. スコープ外（実装しない機能）

本課題の目的（`loader` / `action` の学習）を達成する上で、過剰とみなされる機能。

* 記事の「編集（更新）」機能 (Update)
* ユーザー認証（ログイン、ログアウト）
* データベース、ファイルストレージとの連携
* ページネーション（一覧ページのページ送り）
* コメント機能
